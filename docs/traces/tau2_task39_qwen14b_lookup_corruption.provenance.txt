## What this cannot say yet

  * The TRIGGER relation is not the data path. LangGraph only stamps `versions_seen`
    for a task's trigger channels, which in a StateGraph are the routing channels, so
    the channel carrying the data never appears there.
  * Provenance is per channel, not per message. With one `messages` channel and an
    add_messages reducer every task reads and writes the same channel, so a relation
    means "this task read the state version that included that task's write", not
    "this task read that message".
  * A relation is a data path, not a cause. Nothing here claims the consumer used what
    the producer wrote, only that it was in the state it consumed.
  * Reads are attributed to a task by the super-step it ran in. A node that advanced its
    seen version without writing anything is recorded with the node name and no task id.
